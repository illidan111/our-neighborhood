# Наш район

Браузерный прототип от третьего лица: прогуляйтесь по небольшому району, доставьте припасы в общий дом и решите, куда отнести единственный аккумулятор. Электричества хватит либо убежищу, либо холодильнику магазина. Можно также укрепить мост, затем позвонить в колокол и увидеть последствия грозы.

Один человек и три локальных бота. Физические предметы, общий и личный интерес, три общих исхода и прогулка после финала. Главный герой — лицензированная скелетная аниме-модель pixiv; окружение и аксессуар созданы для проекта. Источники и условия использования: [THIRD_PARTY_ASSETS.md](THIRD_PARTY_ASSETS.md).

## Запуск

Нужны Node.js **22.12 или новее** и npm. Разработка и проверка выполнялись на Node.js 24.

Для установки точных версий из `package-lock.json` используйте `npm ci` вместо `npm install`.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite: при занятом порте он выберет следующий свободный. Выберите имя и цвет, нажмите «Начать прогулку». Клик разрешает браузеру захватить мышь для обзора. Нужны настольный браузер с WebGL, клавиатура и мышь.

```sh
npm test
npm run build
npm run preview
```

Последняя команда запускает просмотр готовой сборки из `dist`. После изменения исходников повторите `npm run build`: preview не пересобирает проект автоматически.

Чтобы каждый раз использовать один адрес для локальных сохранений, запускайте `npm run dev -- --port 5173 --strictPort`. Если порт занят, команда сообщит об этом, а не выберет другой.

## Управление

| Клавиша | Действие |
| --- | --- |
| `WASD` | Движение относительно направления взгляда |
| Мышь | Вращение камеры через Pointer Lock |
| Колесо | Дистанция камеры 2–6 м |
| `Space` | Прыжок |
| `Shift` | Бег |
| `E` | Взаимодействие с предметом, разъёмом, персонажем или колоколом перед прицелом |
| `Q` | Отпустить предмет |
| `G` | Бросить предмет |
| `J` | Дневник, личная записка и история |
| `Escape` | Пауза и освобождение курсора |

В меню паузы доступны чувствительность мыши, звук, три уровня качества и явный масштаб рендера 75–150%. По умолчанию: среднее качество, 100% размера окна. Настройки качества доступны и до начала прогулки. Камера приближается у препятствий; постоянного покачивания нет. Для продолжения нажмите кнопку в меню: браузеру нужен явный клик для повторного захвата мыши.

## Первый маршрут

Игрок появляется внутри общего дома. Выйдите на улицу, найдите ящик у магазина, поднимите и доставьте к полке в доме. Возьмите аккумулятор у генератора, поговорите с Борисом и выберите разъём дома или магазина. Установка окончательная. Доски с площади можно отнести к мосту. Когда готовы, позвоните в колокол на площади.

Личная цель — еда и тепло в убежище. Питание магазина сохраняет продукты для всех, но оставляет дом без обогревателя. После грозы итог находится в дневнике; район остаётся доступен для прогулки, разговоров и переноса оставшихся предметов. Итог уже не меняется.

## Как устроено

React 19, TypeScript, Vite 8, Three.js, React Three Fiber 9 и Rapier через React Three Rapier. Капсула игрока и переносимые тела используют физический движок. Короткие звуки создаются Web Audio после пользовательского клика.

- `src/fps/FPSApp.tsx` — интерфейс, Pointer Lock, пауза, дневник и ход грозы.
- `src/fps/Controller.tsx` и `physics.ts` — управление капсулой, взаимодействия, перенос и бросок.
- `src/fps/Neighborhood.tsx` — район, персонажи и визуальные последствия решений.
- `src/fps/model.ts` — чистые игровые команды, состояние, реакции ботов и исходы.
- `src/fps/storage.ts` — проверяемое автосохранение и импорт архивной кампании.
- `src/fps/audio.ts` — звуковая обратная связь Web Audio.
- [docs/scenario.md](docs/scenario.md) — маршрут, конфликт интересов, правила и архитектура состояния.

Прежние `src/game/`, `src/persistence.ts`, `src/scene/`, `src/ui/` и `src/App.tsx` оставлены в проекте как основа и архив предыдущей реализации. Текущая точка входа запускает версию от третьего лица (каталог `src/fps` сохранён для совместимости). Старые ходы, обещания, доверие и история не удалены, но не рассчитываются заново во время физического эпизода.

## Сохранение

FPS-прогресс хранится в `localStorage` под ключом `our-neighborhood-fps-v2`. После перезагрузки нажмите «Вернуться в район». Установленные объекты и решения сохраняются. Предмет, который был в руках, появляется в безопасном месте внутри дома, руки освобождаются. При сохранённой фазе грозы её короткий показ начинается заново без повторного применения решений.

Прежнее сохранение `our-neighborhood-v1` сохраняется отдельно. Если FPS-слота ещё нет, корректная старая партия импортируется целиком в `state.base`; имя, цвет и seed используются новой прогулкой. Физический день начинается с начала. Сброс FPS-прогресса не удаляет прежнюю кампанию.

Новая игра требует подтверждения. Повреждённый слот не перезаписывается автоматически. Если браузер не разрешает запись, интерфейс сообщает об ошибке. Сохранение привязано к браузеру и адресу сайта, включая порт; облачной синхронизации нет.

## Проверено

- 90 автоматических тестов: прежняя кампания, сценарий и сохранения, реальный Rapier, камера, восстановление позиции, ступени террасы и скелетная анимация.
- Модель проверяет три исхода, независимую личную цель, единственный аккумулятор, повторные команды, восстановление предметов, архив и повреждённые сохранения.
- Проверки физики выполняются в Rapier. Они не заменяют проверку клавиатуры, мыши и Pointer Lock в браузере.
- Актуальный отчёт, production-замеры, кадры и ограничения проверки: [docs/third-person/report.md](docs/third-person/report.md).
- Архив предыдущей версии: [docs/verification-fps.md](docs/verification-fps.md). Старый [docs/verification.md](docs/verification.md) относится к ортографической версии и не подтверждает новое управление.

## Ограничения демо

Это локальная одиночная игра с тремя ботами. Настоящих сетевых участников, приглашений, игрового сервера и LLM нет. API-ключи не нужны; игровая логика не обращается к внешним сервисам. Звуки включаются через Web Audio и могут быть отключены в паузе.

Нужны WebGL и поддержка Pointer Lock. При недоступности 3D отображается сообщение об ошибке. Эта версия рассчитана на настольную клавиатуру и мышь; сенсорное управление не реализовано.

Ориентир длительности — около 8 минут с прогулкой, разговорами и обдумыванием. Он ещё не подтверждён человеческим плейтестом. Реализован один день подготовки и его последствия; дальнейшие игровые дни, совместная переноска, ragdoll и транспорт оставлены для следующих этапов.

## Проверка этой переработки

Резервная рабочая версия: `1bdfc0c014ae23e9c1ef7ef69d1ffbf195637a29`; новая ветка `feat/third-person-anime`. Точное состояние прерванного предыдущего прохода отдельно сохранено в `c8c6c0af47bf8cdbc01a692c40321524d2f2c04d`.

Изолированные инструменты не читают и не меняют игровой прогресс:

- `?heroStudio=1` — настоящий герой, ракурсы, семь состояний и хват предметов.
- `?cameraReview=1` — тот же контроллер/физика/команды с явными кнопками тестового ввода и перемещения между точками. Это не проверка Pointer Lock.
- `?review=1&dpr=1&weather=sun&quality=high` — одинаковый 30-секундный графический маршрут; `weather=storm` проверяет грозу.
- `hero=1` в графическом замере добавляет настоящий VRM и его анимацию; этот прогон отмечен отдельно от сравнения одного окружения.

В доступном Edge использовалась встроенная AMD-графика, а частота автоматизированного окна ограничивалась примерно одним кадром в секунду. Поэтому цель 60 FPS на RTX 3060 Laptop не подтверждена. Отчёт сохраняет исходные frame-time показатели без выдачи этого ограничения за реальную производительность игры.
